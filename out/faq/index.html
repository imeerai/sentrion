HELP / FAQ

Straight answers.

No marketing fog. Here's what Sentrion does, what it needs from you, and what never leaves your laptop. Tap a question to open it.

What does Sentrion actually do?+

It sits in front of any command you run. Before code executes it scans the package; while it runs it watches every file, process and network call; and the moment something malicious happens, it stops it and shows you why. A bouncer for your node_modules.

Which package managers and languages does it cover?+

Installs through npm, pnpm, Yarn, Bun, pip, uv and poetry. Runtime guarding for Node and Python today, with more on the way — and it guards any command’s process tree, whatever language it’s in.

Does it need root or admin?+

No. The core runs as you, with no special privileges. A couple of hardening features — a system-level egress lock, deep kernel tracing — can use an optional helper, but you get full detect-and-kill without ever typing a password.

Will it slow down my installs?+

Barely. In our benchmark a guarded run added about 55 ms. A clean install runs straight through with zero prompts — you only ever stop for something that genuinely looks wrong.

Is my code or are my secrets ever sent anywhere?+

Never. Sentrion runs entirely on your machine and phones nothing home. In fact it does the opposite: it swaps your real tokens for decoys before running untrusted scripts, so even a successful theft grabs a worthless canary.

What if a package genuinely needs an install script?+

Press Trust once. Sentrion remembers that exact package, version range and behaviour — so esbuild compiling a binary is fine forever, but if a future version suddenly phones home, it asks again.

Is it really open source?+

Yes — MIT licensed, zero dependencies, and small enough to read in an afternoon. A security tool that pulls in 300 packages is its own supply-chain risk; Sentrion pulls in none.

A live guard for the software you install and run. Open source, zero dependencies, no root.
