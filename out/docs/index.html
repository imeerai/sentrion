Introduction

New to this? Sentrion is a safety net for the code you install and run. Every time you run npm install or a script someone sent you, you are trusting thousands of lines you have never read — and one bad install script can steal your tokens, open a backdoor, or delete files before you notice.

Sentrion sits in front of every command, watches what the code actually does, and stops it the moment it does something it should not. You do not need to be a security expert — put sentrion in front of your command and it handles the rest. Clean code runs normally; only genuinely risky actions ever stop you.

Brand new? Read these three in order: Installation → Your first guard → The prompt. That is enough to use Sentrion on day one.

Installation

Sentrion is a single Node.js CLI with zero dependencies. Install it globally once and it guards any command on your machine — no per-project setup, no root. You need Node 18 or newer; it runs the same on Linux, macOS and Windows.

Install with whichever package manager you already use:

$ npm install -g sentrion
$ pnpm add -g sentrion
$ yarn global add sentrion
$ bun add -g sentrion

If "sentrion: command not found"

After a global install, this just means npm's global bin folder is not on your PATH (common on Debian and Kali). Either keep using npx sentrion, which always works, or add the folder to your PATH once, then open a new terminal:

$ export PATH="$(npm config get prefix)/bin:$PATH"

Put that line in your ~/.bashrc or ~/.zshrc so it sticks. After that, sentrion works on its own.

On a server or in CI

No global install needed — run it on demand with npx and use enforce mode so it blocks by policy and never waits for a prompt.

$ npx sentrion --mode enforce npm ci

What it can guard

Installs through npm, pnpm, Yarn, Bun, pip, uv and poetry — and any command you run in Node or Python today, with more runtimes on the way. If it spawns a process, Sentrion sees it.

Verify it works

sentrion doctor tells you exactly what your OS lets Sentrion see and block, so there are no surprises later.

$ sentrion doctor
platform macOS 14 · arm64
node hook ok intercepts child_process, net, fs
python hook ok sys.addaudithook via sitecustomize
process tree ok can see and kill descendants
egress lock needs helper base mode still detects + kills

Green rows are active. A yellow row is an optional hardening feature — you still get full detect-and-kill without it. Run sentrion --help for the full flag list.

Your first guard

Put sentrion in front of any command — an install, or a script in any language. Sentrion wraps it, watches the whole process tree, and only steps in when something crosses a line.

$ sentrion npm install express
$ sentrion python3 app.py
$ sentrion pnpm add zod
$ sentrion node build.js

A clean run adds a few milliseconds and never prompts. A risky one pauses and asks — see The prompt.

The four moves

Every guarded command runs through the same four moves. Each has its own command, shown below.

01
Scan before install
Checks a package against the known-malware list, publish age, typosquat distance, and newly added install scripts — before anything runs. Scan on its own, without installing:
$ sentrion scan left-pad
02
Watch at runtime
Hooks into Node and Python and tracks the whole process tree — every file, process and connection. It runs automatically whenever you prefix a command:
$ sentrion <any command>
03
Kill, allow or trust
On a risky event it freezes the process and shows the evidence. Answer with a key — or set a mode so it decides for you (see Modes):
┌ PAUSED [K] Kill [A] Allow once [T] Trust
04
Report & export
Every block becomes one incident per attack chain, as JSON and SARIF. Read the timeline anytime:
$ sentrion report --last

The prompt — Kill / Allow once / Trust

When Sentrion pauses, you get three choices. Here’s exactly what each does, and when to use it.

$ sentrion npm install trusted-pkg
! PROC-01 install script spawned a shell
✕ NET-01 outbound host not in allowlist
┌ PAUSED [K] Kill [A] Allow once [T] Trust
Kill
Ends the command and its whole process tree right away. Nothing it started keeps running; the incident is still written. The safe choice when you're unsure.
Allow once
Lets just this one action through, this single time. Everything else stays watched, and it asks again next run. For a step you know is fine but won't whitelist.
Trust
Remembers this package, version range and behaviour, so it won’t ask again — until something changes, then it asks afresh. For tools that genuinely need an install script.

Modes

Sentrion runs in one of four modes. Set it per run with --mode, or as a default in your policy file.

Mode
What happens, and when to use it
prompt
Pause and ask — Kill / Allow once / Trust. The default; best on your own machine.
enforce
Block by policy, never ask — for servers and CI where no one is watching.
audit
Log only, block nothing — great for your first week, to see what installs actually do.
learn
Record and propose — learns each package’s normal behaviour and suggests allow rules.
$ sentrion --mode enforce npm ci

Commands

The full CLI. Every command is sentrion <command>.

Command
What it does
sentrion <command>
Guard any command and its process tree.
sentrion scan <package>
Pre-flight scan a package without installing it.
sentrion report
Show incidents; --last for the most recent, --sarif to export.
sentrion doctor
Check what your OS lets Sentrion see and block.
sentrion --mode <mode>
Run in prompt / enforce / audit / learn for this command.
sentrion shell-init
Print the shell hook for always-on guarding.
sentrion --help
Every command and flag.

Always-on mode

Tired of typing the prefix? Add one line to your shell and npm, pip, pnpm and friends are guarded automatically — even the installs a build script kicks off behind your back.

$ eval "$(sentrion shell-init)"

Add that line to your ~/.zshrc or ~/.bashrc to make it permanent.

Policy file

Defaults ship built in. Layer a personal policy at ~/.sentrion/policy.json, and a project can add ./.sentrion.json. They merge in that order — and a project policy may only make things stricter, never looser, so a repo can’t quietly weaken your guard.

// .sentrion.json
{ "mode": "enforce",
  "allow": ["esbuild@^0.20"],
  "deny":  ["NET-*"] }

Troubleshooting

A package I trust keeps asking
Its behaviour changed — usually a new version. That’s Trust working as intended. Review the new evidence and press Trust again to pin it.
doctor says the egress lock needs a helper
That’s an optional system feature. Base mode still detects every outbound call and kills it — the helper only adds a kernel-level network lock.
npm itself seems to trigger a file rule
File rules are gated to install scripts, not npm’s own reads of ~/.npmrc. If you still see it, run sentrion doctor — a stale hook is the usual cause, and reinstalling fixes it.
It didn’t prompt in CI
CI has no one to answer, so run it in enforce mode. A pending prompt in CI is treated as a Kill — fail-closed.
